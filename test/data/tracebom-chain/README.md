# tracebom observed-chain fixtures

Generated by `gen.sh`; do not edit by hand. Regenerate from the repo root:

```sh
./test/data/tracebom-chain/gen.sh
```

The script builds two 3-level PKIs, serves one TLS 1.2 server per chain plus
a TLS 1.3 server (ports 9440–9442 when free, else the next free port up to
9459), and drives `curl` through `bin/tracebom.js` with `--proxy-egress` and
crypto tracing, capturing:

| File | What it is |
|---|---|
| `crypto-result.json` | the raw safer-exec `CRYPTO:` result (report channel) of the workload |
| `bom.json` | the CBOM `bin/tracebom.js` produced (spec 1.7) |
| `bom-1.6.json` | the same run with `--spec-version 1.6` |
| `c-leaf/c-int/c-root.pem` | the classical chain's public certificates (RSA root → RSA intermediate → ECDSA P-256 leaf) |
| `h-leaf/h-int/h-root.pem` | the hybrid chain's public certificates (ML-DSA-65 root → ML-DSA-44 intermediate → ECDSA P-256 leaf) |
| `capture-crypto.mjs` | the helper that captures the crypto result through cdxgen's own `executeAndTrace` |

All leaves have `CN=localhost` and `subjectAltName=DNS:localhost,IP:127.0.0.1`.
The private keys never leave the script's temp directory, which is deleted on
exit; nothing secret is committed.

## Gotchas baked into the script

- `curl --noproxy ""` is required: safer-exec's proxy sets `NO_PROXY` to cover
  loopback, and without the override curl bypasses the tunnel, so the chain is
  never observed.
- The workload reaches the servers by the name `localhost`, not `127.0.0.1`:
  the proxy pins hostnames, and cdxgen resolves `--allow-host` values with the
  DNS resolver, which cannot resolve an IP literal — an IP target is always
  denied.
